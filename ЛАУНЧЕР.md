# Overdeck — лаунчер (Overdeck.exe)

`Overdeck.exe` в корне проекта заменяет `start.bat` и `start-silent.vbs`: запускает сервер оверлея в фоне и открывает админку. Сервер сам не стартует: после открытия лаунчер сначала проверяет обновления, а сервер и админка запускаются кнопкой «Запустить сервер».

## Что в окне
- **Версия** оверлея (берётся из `package.json`) и состояние сервера (работает / запускается / остановлен, порт из `config.json`).
- **Открыть админку** — `http://localhost:<порт>/admin` в браузере.
- **Открыть консоль** — окно с выводом сервера (баннер STARIKOV, ошибки, сообщения чата и т.д.), как при обычном старте. История сохраняется, пока лаунчер запущен.
- **Проверить обновления** — см. ниже. Автоматически проверяет один раз при запуске.
- **Запустить / Остановить сервер**.

Закрытие окна сворачивает лаунчер в трей, сервер продолжает работать. Полностью выйти (и остановить сервер): правый клик по значку в трее → «Выход». Повторный запуск Overdeck.exe при уже работающем лаунчере просто открывает админку.

## Первый запуск
- Нужен Node.js (https://nodejs.org, версия LTS). Если его нет, лаунчер подскажет.
- Если нет папки `node_modules`, лаунчер сам выполнит `npm install` (прогресс — в окне консоли).
- Overdeck.exe должен лежать в корне папки проекта (рядом с `server.js`). Можно сделать ярлык на рабочий стол.

## Автообновление
Лаунчер при каждом запуске (и по кнопке «Проверить обновления») смотрит последний релиз репозитория. Если версия новее, чем в твоём `package.json`, он сам:
1. скачивает архив релиза (приложенный к релизу `.zip`, а если его нет — исходный архив тега),
2. останавливает сервер и распаковывает файлы ПОВЕРХ папки проекта — личные данные (`config.json`, настройки, фото, токены) в архиве отсутствуют и не затрагиваются; `launcher.json` не перезаписывается,
3. подменяет сам `Overdeck.exe`, при изменении списка зависимостей выполняет `npm install`,
4. перезапускает лаунчер и сервер; в трее появляется уведомление «Overdeck обновлён».
После установки обновления (и при первом запуске новой версии) лаунчер открывает окно **«Что нового»** с описанием релиза (пачноутом). Версия, для которой окно уже показано, запоминается в `launcher.state`.
Галочка **«Обновлять автоматически»** в окне выключает это: тогда при новой версии кнопка превращается в «Обновить до X.Y.Z», и установка идёт по клику. Настройка хранится в `launcher.json` (`"autoUpdate"`).
Адрес источника — поле `updateUrl` в `launcher.json` (по умолчанию — релизы этого репозитория GitHub). Поддерживается и свой JSON: `{ "version": "2.1.0", "download": "https://…/архив.zip", "url": "страница", "notes": "что нового" }`.
Нужен .NET Framework 4.5+ (есть в Windows 10/11).

## Пересборка
Исходник — `launcher/Overdeck.cs`. Двойной клик по `build-launcher.bat` пересоберёт `Overdeck.exe` штатным компилятором Windows (ничего ставить не нужно).

## Как выпустить обновление (для владельца репозитория)
1. Подними версию в `package.json` (например, `2.0.0` → `2.1.0`) и залей изменения в репозиторий.
2. На GitHub: *Releases → Draft a new release*, тег `2.1.0` (можно с `v`), в описание напиши, что нового, приложи архив проекта.
3. Лаунчеры у всех, кто запустит Overdeck.exe (или нажмёт «Проверить обновления»), сравнят тег с версией из своего `package.json` и покажут «Доступна новая версия» со ссылкой на страницу релиза.
Дальше всё делают лаунчеры пользователей автоматически.
